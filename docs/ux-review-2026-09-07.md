# Dink Derby UX review — September 7, 2026

## Outcome and scope

Reviewed the working app's profile, derby list, creation, joining, invitations,
catch entry, chat, standings, rules, completion, and historical results. Implemented
the control and recovery improvements below in the existing Dink Derby client.
This initially shipped as a local UX pass. The subsequent authorized release
also implemented catch corrections and addressable navigation, and is now live.
See [the September 7 deployment record](deployment-2026-09-07.md) for current
verification and deployment details.

The client guidance informed the changes: readable controls, at least 44px targets
for the main actions, one catch-entry screen, and local-first saving. The React
review covered effects, focus restoration, pending states, and photo URL cleanup.

## Findings and changes

| Area | Problem | Implemented change |
| --- | --- | --- |
| Completion | Finishing was buried in Rules. A generic management menu would still add an unnecessary step. | Organizer-only **Finish derby** beside the derby name. One confirmation reviews the leader/biggest fish and explains closing entry, history, and late offline catches. **Keep fishing** cancels. |
| Catch entry | Multiple catch buttons competed; the photo picker preceded the required measurement. | One persistent **Log a catch** action with a fish icon. Measurement first; count derbies clearly add one fish without a measurement. Species/photo remain optional. |
| Optional information | Optional details made the common catch flow long. Location could delay every save. | Note/location are collapsed under an explicit optional section. Location collection is opt-in. The empty photo picker is smaller. |
| Validation | Disabled submits concealed why the form could not be saved. | Empty required measurements use native validation and focus the field. Whitespace-only profile/derby names receive a readable error. Decimal-pound examples clarify the unit. |
| Draft recovery | Closing was ambiguous; persistence failure could still dismiss the form. | **Save draft & close** explicitly keeps a draft. A failed draft write now leaves the form and values open for recovery; a regression test covers quota failure and retry. |
| Invitations | A raw invite code did not explain the tap action; failed copy could claim success. | **Invite anglers** opens a selectable code and labeled **Copy invite code** action. Clipboard failure provides manual-copy instructions. Join accepts pasted lowercase/spaced codes and preserves them after failure. |
| Navigation | Four tabs and oversized/duplicated header content pushed useful controls down. | Three sections: **Catches & chat**, **Standings/Results**, **Rules & info**. Activity is available from Rules. Compact header, no empty leader panel, no duplicate sync badge on derby screens. |
| History | Returning from results reset the list to active derbies; cards lacked a clear destination. | Back from a completed derby returns to **Past derbies**. Cards explicitly say **Open derby** or **View results**, with readable scoring rules. |
| Sync status | Color alone and overly broad success wording could mislead. | Visible phone-size status text and retry action. Catch counts no longer imply that every type of change has synced. Local completion remains explicitly pending until server confirmation. |
| Chat | Icon-only send and weak failure feedback. | Labeled **Send**, disabled for blank text/in-flight saves. Save failure keeps the message text and displays an error. |
| Dialogs | Inconsistent close controls, accidental backdrop dismissal, and keyboard escape paths. | Shared dialog with a labeled close action, scroll lock, focus containment/restoration, Escape handling, and busy-state protection. Backdrop clicks do not discard forms. |
| Feedback overlays | A catch-saved toast could intercept confirmation taps. | Notifications no longer receive pointer events; the global toast is hidden while a dialog is open. |
| Readability | Decorative context, small actions, and heavy effects competed with app controls. | Smaller headers/cards, enlarged main tap targets, 16px form inputs, visible focus rings, no grain overlay or backdrop blur. Working-app text describes the action/state. |
| Profile | Initials were an obscure edit control; storage quota could be mistaken for RAM. | Visible **Profile** button. Technical storage information is collapsed and explicitly described as storage, not phone memory. Browser-bound identity is disclosed. |

## Initial review verification

- 45 unit/component tests passed, including the new failed-draft-close test.
- 7 isolated Chromium browser tests passed in a single run. Coverage includes
  scoring, one-fish count entries, optional photos, oversized-photo handling,
  offline saving, reload/draft recovery, finish/cancel, historical results,
  clipboard failure, join failure, blank-name validation, and chat saving.
- The UX flow was tested at 320×740, 375×812, and 1280×900 CSS pixels. Main-action
  target sizes, no horizontal page overflow, the visible finish action, one catch
  action, keyboard focus loops, and focus restoration are asserted.
- Phone and desktop screenshots were visually inspected. The local preview uses
  an intentionally unavailable API, so its server-unavailable warning is expected;
  test data does not go to the live service.
- Client TypeScript/production build passed. The existing >500KB minified bundle
  warning remains; this review is not a claim that physical-phone RAM issues are
  eliminated.
- Earlier serial browser runs were interrupted by long host pauses. The final
  concurrent isolated run completed normally: all seven tests passed.

Reproduce from the repository root:

```sh
npm run test -w @dink-derby/client
npm run build -w @dink-derby/client
```

From `apps/client`:

```sh
npx playwright test --config=playwright.local.config.ts --project=mobile-chromium --workers=3
```

## Resolved in the follow-up release

- Submitted catches can now be edited, removed, and restored by their owner while
  the derby is active. Removals are soft-deletes, retained for synchronization and
  restoration. Completed derbies remain locked.
- Derby sections and the Past derbies list now have query-based URLs that survive
  reload and support browser Back/Forward. Explicit derby URLs take precedence
  over an unrelated old draft.

## Remaining UX/product gaps

1. **Same angler across devices / recovery.** The profile is still browser-bound.
   Explaining that is useful, but is not a replacement for a linking/recovery flow.
2. **Post-creation changes.** Rules editing and reopening a finished derby are not
   exposed. The finish confirmation explicitly says completion cannot be undone
   here; no nonfunctional management controls were added.
3. **Real field validation.** Physical Android Chrome/iOS Safari, native camera
   and keyboard behavior, sunlight readability, and long sessions on a low-memory
   phone need hands-on testing. Automated layout checks do not prove intuitive
   behavior for first-time anglers or resolve the prior on-water memory report.

Live deployment and production two-device verification are complete as recorded
in the release note. They used dedicated synthetic QA derbies; existing user
derbies were not changed.
